## 📊 System Design Fundamentals

### Database Scaling
```
Vertical Scaling (Single server, bigger)
├─ Easier initially
├─ Limited by hardware
├─ Good for: <1M requests/day
└─ Example: Larger PostgreSQL server

Horizontal Scaling (Multiple servers)
├─ Read replicas (PostgreSQL)
├─ Sharding (split data)
├─ Replication (MongoDB)
└─ Good for: >10M requests/day

Caching Layer
├─ Query caching (Redis)
├─ Object caching (memcached)
├─ HTTP caching (CDN)
└─ Good for: 3-5x performance improvement
```

### API Design Patterns
```
REST (Representational State Transfer)
├─ HTTP methods: GET, POST, PUT, DELETE
├─ Status codes meaningful
├─ Resources-oriented
├─ Best for: Most APIs
├─ Example: /api/users/{id}

GraphQL
├─ Strongly typed schema
├─ Client requests exactly what it needs
├─ Single endpoint
├─ Best for: Complex, interconnected data
├─ Example: query { user { name posts { title } } }

gRPC
├─ Protocol Buffers for serialization
├─ HTTP/2 for performance
├─ Strongly typed
├─ Best for: Microservices, high performance
└─ Example: internal service-to-service
```

### Handling Scale
```
10k Requests/Day
├─ Simple setup
├─ Single database OK
├─ No caching needed usually
└─ Deployment: Heroku, simple

100k Requests/Day
├─ Database optimization important
├─ Basic caching (Redis)
├─ Load balancing
└─ Deployment: 2-3 servers

1M Requests/Day
├─ Database replication/sharding
├─ Advanced caching
├─ Message queues
├─ Multiple service instances
└─ Monitoring essential

100M+ Requests/Day
├─ Microservices architecture
├─ Global distribution
├─ Advanced optimization
├─ Dedicated teams per system
└─ Custom solutions common
```

## 🎯 Interview Preparation

### Technical Interview (2-3 hours)

**Coding Round (45-60 minutes)**
```
Typical: Medium LeetCode problems
Topics:
- Arrays, strings, hashing
- Trees, graphs, traversal
- Dynamic programming (sometimes)
- Database queries (SQL)

Example: "Find users who made purchases > $100 last month"
- Write SQL query
- Discuss indexes
- Optimization techniques
```

**System Design Round (45-90 minutes)**
```
1. Clarifying Questions (5-10 min)
   - Scale? (Users, RPS, data volume)
   - Key features?
   - Performance requirements?

2. High-Level Design (15-20 min)
   - Architecture diagram
   - API design
   - Database schema

3. Deep Dive (15-20 min)
   - Database indexing/optimization
   - Caching strategy
   - Error handling
   - Scalability challenges

4. Trade-offs (10 min)
   - Why these choices?
   - Alternatives?
   - Cost vs performance?

Typical Questions:
- Design Instagram (real-time feed)
- Design Uber (real-time location)
- Design Amazon (e-commerce at scale)
- Design Spotify (music streaming)
```

### Behavioral Interview
```
Common Questions:
1. "Tell me about a challenging project"
   → Focus: Problem, your solution, learning

2. "How do you handle technical disagreement?"
   → Focus: Communication, openness, compromise

3. "What's your experience with scale?"
   → Focus: Actual numbers, what you learned

4. "Describe your testing approach"
   → Focus: Practical, balanced (unit + integration)

STAR Method: Situation → Task → Action → Result
```
